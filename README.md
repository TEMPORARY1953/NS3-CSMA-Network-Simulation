## Запуск

Нужны C++-компилятор, CMake, Python 3, установленное дерево исходников ns-3
с современной командой `./ns3` (ориентир — ns-3.40 и новее).
Сборка и реальные прогоны проверены на ns-3.49.
Команды выполняются обычным пользователем, без `sudo` для сборки и запуска.

Если ns-3 ещё не установлен, на машине с интернетом можно собрать релиз:

```bash
curl -LO https://www.nsnam.org/releases/ns-3.46.1.tar.bz2
tar xjf ns-3.46.1.tar.bz2
cd ns-3.46.1
```

В дереве ns-3:

```bash
cp '/home/vova/Имирисы/HW3/csma-v3.cc' scratch/csma-v3.cc
./ns3 configure --build-profile=optimized --enable-modules=csma
./ns3 build csma-v3
./ns3 run --no-build 'csma-v3 --n=10 --alpha=10 --dist=exp --seed=12345 --run=1'
```

Модуль `csma` подтягивает зависимости `core` и `network`.
Если дерево уже настроено с нужными модулями, достаточно копирования и сборки.
В другой системе замените абсолютный путь к заданию на свой.

Зависимости скрипта можно установить в обычное виртуальное окружение:

```bash
cd '/home/vova/Имирисы/HW3'
python3 -m venv .venv
.venv/bin/python -m pip install scipy matplotlib
.venv/bin/python experiments.py --ns3 /полный/путь/ns-3.46.1
```

Либо используйте `python3`, если SciPy и Matplotlib уже установлены.
Скрипт находит собранный исполняемый файл в `build/scratch` и запускает его
напрямую, без повторной сборки и накладных расходов `./ns3` на каждом повторении.
При нестандартном расположении используйте `--binary /полный/путь/к/исполняемому/csma-v3`.
Параметр `--jobs 16` запускает до 16 независимых прогонов одновременно.
Он не меняет seed/run, порядок записей и расчёт показателей; по умолчанию `--jobs 1`.

Одна комбинация для первого запуска:

```bash
python3 experiments.py --ns3 /полный/путь/ns-3.46.1 \
  --alphas 100 --distributions exp --out results-check
```

Полная серия — все три α и оба закона — включена по умолчанию.
Результаты появятся в `results/`:

| Файл | Содержимое |
|---|---|
| `raw.jsonl` | Идентификация сборки, seed/run, исходные счётчики каждого прогона; фазы pilot и measure |
| `summary.csv` | Средние, границы ДИ, полуширины, относительные полуширины, статусы для каждого N |
| `boundaries.json` | Две найденные границы на каждую комбинацию α и закона, соседнее N и статус |
| `results.md` | Готовые таблицы двух экспериментов и всех четырёх характеристик |
| `alpha-10.png`, `alpha-50.png`, `alpha-100.png` | Зависимости потерь, повторов, очередей и занятости от N |

Код возврата 0 означает, что для рассчитанных точек достигнута требуемая
точность ненулевых средних и найдены соседние границы при принятой монотонности.
Код 2 — таблицы сохранены, но исследование не закончено: недостаточная
точность, неопределённость порога, ограничение диапазона или нарушение монотонности.
Код 1 — ошибка запуска/данных. Отдельные нулевые выборки не получают фиктивный ДИ `[0,0]`.

Повторный запуск с тем же `--out` использует сохранённые прогоны. Например:

```bash
python3 experiments.py --ns3 /полный/путь/ns-3.46.1 \
  --max-runs 16384 --max-n 16384 --out results
```

Не уменьшайте `--max-runs` ниже уже сохранённого числа повторений.
При смене сборки, кода модели или базового seed используйте новый каталог `--out`.
Редкие ненулевые потери и очень маленькая средняя очередь могут потребовать
значительно больше 4096 повторений: это лимит по умолчанию, а не обещание точности.
Повышайте его по фактическим статусам. При изменении лимита пересчитываются поправки ДИ.

## Определения и учёт

Основа — `lecture_zadanie3(1) (1).pdf`, слайды 6–9, и `lecture_ns3.pdf`,
слайды 8–16 и 22: сборка модели из стандартных узлов, устройств, канала,
планировщика событий и трассировок.

Каждый из N узлов имеет один `CsmaNetDevice`; все устройства подключены
через `CsmaHelper` к одному каналу 100 Мбит/с. Длину 30 м преобразуем в
задержку 150 нс при явно принятой скорости распространения 2·10⁸ м/с.
В модели ns-3 задаётся задержка канала, отдельного параметра длины нет.
Коллизии не добавляются. Backoff и межкадровый интервал стандартные.

На вход `NetDevice::Send` поступает **пакет 1500 байт**. При DIX-инкапсуляции
ns-3 добавляет Ethernet-заголовок и FCS: время сериализации рассчитывается
по фактическому размеру кадра (1518 байт, 121,44 мкс при 100 Мбит/с).
IP/UDP и ARP не используются, чтобы не менять размер и число создаваемых пакетов.
Адресат — следующий узел по кольцевой нумерации; физическая топология остаётся общей шиной.
Ответов и дополнительного трафика нет. При N=1 измеряется работа передатчика.

Независимый генератор каждого узла имеет собственный RNG stream.
Первый пакет также появляется после случайного интервала; синхронной отправки
всеми узлами в t=0 нет. Каждый следующий интервал выбирается независимо
от результата `Send`, завершения передачи и состояния очереди:
Exp со средним 1/α либо U(0,2/α), α ∈ {10,50,100} пакетов/с.

Очередь `DropTailQueue<Packet>` ограничена `MaxSize=20p`.
Это 20 ожидающих пакетов **в очереди**, без текущего пакета, уже извлечённого
устройством для передачи/backoff. Таким образом, устройство может иметь
20 пакетов в очереди и ещё один обслуживаемый пакет. Это семантика стандартного
`CsmaNetDevice`, а не дополнительная очередь в приложении.

Генерация идёт только в `[0,10)` с пустыми начальными очередями, без прогрева.
В t=10 снимается состояние. Затем без новых поступлений сеть дорабатывает
всю созданную когорту до передачи или действительного сброса. Продолжительность
наблюдения очереди и канала остаётся 10 с; время доработки в неё не входит.
Остаток в t=10 не записывается в потери. В JSON есть `queued_at_10`,
`unfinished_at_10`, `tx_end_at_10` и `drain_end_s` для проверки.

Пусть G — все созданные пакеты, Dq — отказы очереди, Dp — сбросы при обслуживании,
A=G−Dq — принятые устройствами пакеты, K — число событий `MacTxBackoff`.
Для одного повторения считаются:

| Характеристика | Определение |
|---|---|
| 1. Доля потерь | (Dq+Dp)/G; Dq считается через `MacTxDrop` и сверяется с `Queue::Drop`, без двойного счёта |
| 2. Среднее число повторов | K/A за всю жизнь принятой когорты; включая пакеты с нулём повторов и возможные Dp |
| 3. Средняя очередь | Σᵢ ∫₀¹⁰ Qᵢ(t)dt / (10N), по `PacketsInQueue`, а не по нерегулярным отсчётам |
| 3. Максимальная очередь | maxᵢ,ₜ Qᵢ(t) при t∈[0,10); наблюдаемый максимум по узлам и повторам |
| 4. Занятость | Длина объединения интервалов `[PhyTxBegin, PhyTxBegin + размер_кадра/B + Delay)` внутри `[0,10)` / 10 |

Знаменатель A в хар. 2 выбран явно: пакет, не принятый заполненной очередью,
не делал попыток доступа. Это не среднее только среди успешно переданных и
не среднее только среди пакетов с backoff; начальная попытка не прибавляется к K.
Оба поиска выполняются с одной и той же очередью 20 пакетов.

Занятость включает состояния `TRANSMITTING` и `PROPAGATING`, когда канал
действительно недоступен. Backoff и IFG сами по себе занятостью не считаются.
В стандартном CSMA интервалы не перекрываются, что проверяется в коде;
последний интервал обрезается границей 10 с.

После доработки проверяются G=Dq+Dp+TxEnd, A=число извлечённых из очередей,
пустые очереди, совпадение счётчиков сбросов очереди и MAC, отсутствие
незавершённых начатых передач, диапазоны Q и занятости.

## Повторения, ДИ и поиск N

Единица статистического наблюдения — независимый **10-секундный прогон**,
а не отдельный пакет. Средняя доля потерь — среднее по долям отдельных прогонов;
прочие характеристики также усредняются по прогонам. Максимумы не усредняются
вместо максимума: отдельно выводятся среднее максимума за прогон с ДИ и общий
наблюдаемый максимум. ДИ для «истинного максимума» не утверждается.

Seed различается между шестью комбинациями и фазами pilot/measure,
run — между N и повторениями. При фиксированном N меняется run/substream.
Номера потоков источников и backoff не пересекаются в предусмотренном диапазоне N.
Поисковые прогоны не включаются в итоговые средние.

Сначала 8 поисковых прогонов на точку: геометрическое расширение диапазона
и целочисленный двоичный поиск. На независимых измерительных прогонах поиск
повторяется от найденного ориентира: 32, 64, …, 4096 повторений по умолчанию.
Проверяются соседние N и N+1, окрестность границ и несколько более высоких N.
Для графиков добавляется небольшой набор значений ниже и выше границ.

Для ненулевого среднего x̄ рассчитываются s и полуширина h=t·s/√R.
Требуется h/x̄≤0,05 для четырёх средних: доли потерь, повторов, средней очереди
и занятости. Наблюдаемый Qmax выводится отдельно; точность среднего максимума
за прогон не является требованием задания и не задерживает остановку серии.
Чтобы учесть повторные проверки точности,
ошибка 0,01 делится на пять показателей и число запланированных просмотров.
Полученные ДИ шире обычных 99%-х; их совместное покрытие для фиксированного N
приближённо не ниже 99% по поправке Бонферрони и нормальной/ЦПТ-аппроксимации.
Для редких событий t-интервалы остаются приближёнными. Поправка не даёт
совместной гарантии для всех адаптивно выбранных N и для найденной границы.

Для хар. 2 допустимость проверяется консервативно: верхняя граница ДИ ≤2;
недопустимость — нижняя граница >2. Если даже при лимите повторений ДИ
пересекает 2, граница помечается `uncertain` и не объявляется найденным максимумом.

Для потерь допустимость означает отсутствие **наблюдаемых** потерь во всех
измерительных прогонах этого N. Это эмпирическая граница, зависящая от числа
повторений, начального состояния и seed/run; доказать нулевую вероятность
потерь конечной серией нельзя. Если все значения равны нулю, выводится
«не наблюдалось», ДИ среднего не оценивается. Независимость пакетов для
фиктивной биномиальной оценки не предполагается.

Поиск предполагает монотонность критериев по N. Она не доказывается:
скрипт проверяет согласованность всех исследованных точек и при обратном
переходе выставляет `nonmonotone_observed`. Никакая конечная выборка N без
полного перебора не исключает пропущенных нарушений. Поэтому результаты
нельзя объявлять доказанным глобальным максимумом. Случайная немонотонность
конечных наблюдений сама по себе не означает ошибки модели.

Для потерь поле `loss.n` в `boundaries.json` и таблица `results.md` показывают
наибольшее **исследованное измерительное N** без наблюдаемых потерь.
`next_n` — ближайшее исследованное N выше него с потерями, не обязательно N+1.
В `REPORT.md` дополнительно приведён максимум по всем записанным прогонам,
включая поисковые, с явным указанием их числа и фазы. Эти значения также
сохранены в полях `observed_all_n`, `observed_all_runs`, `observed_all_phases`
внутри `loss` в `boundaries.json`. Поисковые прогоны
не добавляются к итоговым средним и доверительным интервалам.

Описание стандартной модели и трассировок сверено с
[CSMA NetDevice, ns-3 Model Library](https://www.nsnam.org/docs/release/3.46/models/html/csma.html)
и [исходником CsmaNetDevice](https://www.nsnam.org/doxygen/d7/d05/csma-net-device_8cc_source.html).

Для ограниченного завершения в текущих результатах `retries.n` — наибольшее
измеренное N с выборочным средним повторов ≤2. При `uncertain` это оценка:
`confirmed_n` имеет верхнюю границу ДИ ≤2, `rejected_n` — нижнюю >2.
Точный порог внутри этого диапазона не установлен; дополнительные серии
для его строгого разделения в этот отчёт не включены.
